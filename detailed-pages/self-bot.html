T v0.1 ELEGRAM LEAD INTELLIGENCE

Project: self-bot — a multi-tenant, event-driven SaaS for Telegram lead detection that ingests group/channel messages, scores buying intent, and alerts tenants via Saved Messages.

پروژه: self-bot — یک SaaS چند‌مستاجره و رویداد-محور برای شناسایی لید در تلگرام که پیام‌های گروه/کانال را دریافت، نیت خرید را امتیازدهی و از طریق Saved Messages به مستاجر هشدار می‌دهد.

Sales and agency teams miss buying-intent messages buried in Telegram groups and channels. self-bot is a multi-tenant, event-driven SaaS that authenticates tenant Telegram accounts, runs a license-gated listening engine, scores leads as low / warm / hot, and notifies tenants via Telegram Saved Messages.

تیم‌های فروش و آژانس پیام‌های دارای نیت خرید را در گروه‌ها و کانال‌های تلگرام از دست می‌دهند. self-bot یک SaaS چندمستاجره و رویدادمحور است که حساب تلگرام مستاجر را احراز می‌کند، موتور شنود را با لایسنس کنترل می‌کند، لیدها را low / warm / hot امتیازدهی می‌کند و از طریق Saved Messages اطلاع می‌دهد.

Five-step pipeline

خط لوله پنج‌مرحله‌ای

  1. Authenticate tenant Telegram account (Pyrogram string session stored in PostgreSQL).
  2. Start/stop listening engine from /dashboard, gated by is_active and subscription_end.
  3. Ingest group/channel messages (Telethon listener) and enqueue matching via Celery + Redis.
  4. Score matches with RapidFuzz, keyword presets, and custom keywords.
  5. Persist leads and notify tenant via Telegram Saved Messages.
  1. احراز هویت حساب تلگرام مستاجر (session string در PostgreSQL).
  2. شروع/توقف موتور شنود از داشبورد، با کنترل is_active و subscription_end.
  3. دریافت پیام گروه/کانال (Telethon) و صف‌بندی Celery + Redis.
  4. امتیازدهی با RapidFuzz، preset و کلمات سفارشی.
  5. ذخیره لید و اعلان Saved Messages.

Control and data sequence (§2.3)

توالی کنترل و داده (§2.3)

sequenceDiagram
  participant U as Tenant dashboard
  participant API as FastAPI
  participant PG as PostgreSQL
  participant R as Redis
  participant L as Listener
  participant W as Celery worker
  participant TG as Telegram
  U->>API: POST /api/v1/engine/start Bearer JWT
  API->>PG: Check is_active, subscription_end, telegram_sessions
  API->>PG: Load custom keywords + merge with presets
  API->>R: SET user:{id}:keywords JSON
  API->>PG: UPDATE telegram_sessions.is_engine_active = true
  API->>R: SET user:{id}:status engine_active/license_valid
  API->>R: PUBLISH engine:control start
  API-->>U: EngineActionResponse + pipeline steps
  L->>PG: SELECT sessions WHERE is_active AND is_engine_active
  TG->>L: NewMessage group/channel
  L->>W: Celery tasks.process_raw_message
  W->>R: GET user:{id}:status
  alt engine_active and license_valid
    W->>R: GET user:{id}:keywords
    W->>W: RapidFuzz match
    W->>PG: Persist source/person/message/lead
    W->>TG: Saved Messages notification
  else
    W-->>W: Ignore message
  end

PostgreSQL holds canonical tenant and lead data; Redis holds hot keyword merges, engine status, pub/sub control, and Celery broker state. Tenant isolation is users.id; sources / persons / messages are shared Telegram graph entities.

PostgreSQL داده مستاجر و لید را نگه می‌دارد؛ Redis کلمات، وضعیت موتور و Celery را. جداسازی با users.id است؛ sources/persons/messages گراف مشترک تلگرام‌اند.

CORS & CSRF (§7.3)

CORS و CSRF (§7.3)

Same-origin Jinja UI; fetch uses Bearer from localStorage. No CORS middleware — do not host SPA on another origin without explicit CORS. XSS can steal localStorage tokens.

UI هم‌مبدأ؛ Bearer در localStorage. CORS پیکربندی نشده.
