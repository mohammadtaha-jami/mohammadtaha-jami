The Video Playback Performance Testing Suite (View-Aparat) is a desktop monolith written in Python. A CustomTkinter GUI orchestrates Playwright Chromium workers to stress-test video playback on Aparat and YouTube under concurrent, long-running load, simulating returning viewers via persistent browser profiles on disk. It is not a client–server web application — there is no HTTP API layer, no relational database, and persistence is entirely file-based (JSON reports, text proxy lists, Playwright user-data directories).

مجموعه تست عملکرد پخش ویدیو (View-Aparat) یک اپلیکیشن دسکتاپ مونولیتیک نوشته‌شده با پایتون است. یک رابط گرافیکی CustomTkinter، Workerهای Playwright Chromium را برای تست فشار پخش ویدیو روی آپارات و یوتیوب تحت بار همزمان و طولانی‌مدت هماهنگ می‌کند و با استفاده از پروفایل‌های ماندگار مرورگر، بازدیدکنندگان بازگشتی را شبیه‌سازی می‌کند. این یک اپلیکیشن وب کلاینت-سرور نیست — هیچ لایه API از نوع HTTP و هیچ پایگاه‌داده رابطه‌ای وجود ندارد و ماندگاری داده کاملاً فایل‌محور است (گزارش‌های JSON، فهرست‌های متنی پروکسی، دایرکتوری‌های Playwright).

  1. O-1Run N concurrent Playwright workers with isolated persistent profiles — worker i always maps to session_data/worker_i.اجرای N Worker همزمان Playwright با پروفایل‌های ماندگار مجزا — Worker شماره i همیشه به session_data/worker_i نگاشت می‌شود.

A monolith with layered modules: main.py (presentation) → suite/* (domain) → Playwright / file I/O. The UI is event-driven — a queue.Queue bridges background threads to the Tk main loop — with an async worker pool (asyncio.create_task per worker round) inside run_manager(). Persistence (reports, sessions, proxy lists) is entirely file-backed, with no ORM.

یک مونولیت با ماژول‌های لایه‌ای: main.py (نمایش) → suite/* (دامنه) → Playwright / I/O فایل. رابط کاربری رویدادمحور است — یک queue.Queue بین Threadهای پس‌زمینه و حلقه اصلی Tk پل می‌زند — همراه با یک استخر Worker ناهمزمان (asyncio.create_task برای هر دور Worker) داخل run_manager(). ماندگاری داده (گزارش‌ها، نشست‌ها، فهرست‌های پروکسی) کاملاً فایل‌محور است، بدون ORM.

There is no relational database. All durable state is stored as JSON run/bot-test reports, Chromium user-data directories per worker, plain-text proxy lists, and a user-editable warm-up catalog. Relationships shown below are logical — embedded JSON and directory naming, not SQL foreign keys.

هیچ پایگاه‌داده رابطه‌ای وجود ندارد. تمام وضعیت پایدار به‌صورت گزارش‌های JSON اجرا/تست ربات، دایرکتوری‌های Chromium برای هر Worker، فهرست‌های متنی پروکسی و کاتالوگ گرم‌کردن قابل‌ویرایش ذخیره می‌شود. روابط زیر منطقی هستند — JSON تعبیه‌شده و نام‌گذاری دایرکتوری، نه کلید خارجی SQL.

Session Profile Layout

آرایش پروفایل نشست

Worker i always uses session_data/worker_i across all runs and modes. Directories are created if missing, never deleted by the application. Increasing concurrency only creates new worker_{N+1} folders.

Worker شماره i همیشه از session_data/worker_i در تمام اجراها و حالت‌ها استفاده می‌کند. دایرکتوری‌ها در صورت نبود ساخته می‌شوند و هرگز توسط اپلیکیشن حذف نمی‌شوند. افزایش همزمانی فقط پوشه‌های worker_{N+1} جدید می‌سازد.

This application does not expose HTTP REST endpoints. The interfaces below define how operators and modules interact with the system: the GUI entry point, the core run_manager() orchestrator, the resume interface, standalone tool interfaces, and the external service contracts it consumes.

این اپلیکیشن هیچ Endpoint از نوع HTTP REST ارائه نمی‌دهد. رابط‌های زیر نحوه تعامل اپراتورها و ماژول‌ها با سیستم را تعریف می‌کنند: نقطه ورود GUI، هماهنگ‌کننده اصلی run_manager()، رابط ازسرگیری، رابط‌های ابزار مستقل و قراردادهای سرویس خارجی مصرف‌شده.

Server Setup Checklist

چک‌لیست راه‌اندازی سرور

  1. 1.Provision a VM with display or Xvfb for GUI, or refactor to a CLI entry for headless.
  2. 2.Install Python 3.12 + Chromium system deps (playwright install-deps).
  3. 3.Mount persistent volumes for session_data/, reports/, secrets.
  4. 4.Restrict outbound network to required domains.
  5. 5.Store client_secrets.json / token.json on an encrypted volume (permissions 600).
  6. 6.Schedule proxy_collector.py or proxy_downloader.py via cron/systemd timer.
  1. ۱.تهیه یک VM با نمایشگر یا Xvfb برای GUI، یا بازطراحی برای اجرای بدون نمایشگر.
  2. ۲.نصب Python 3.12 و وابستگی‌های سیستمی Chromium.
  3. ۳.مانت کردن Volumeهای ماندگار برای session_data/، reports/ و اسرار.
  4. ۴.محدود کردن شبکه خروجی به دامنه‌های ضروری.
  5. ۵.نگهداری client_secrets.json / token.json روی Volume رمزنگاری‌شده (مجوز 600).
  6. ۶.زمان‌بندی proxy_collector.py یا proxy_downloader.py با cron/systemd.

There is no RBAC, JWT, or session middleware — this is a single-operator desktop app. Physical access to the machine equals full access. Google Drive access uses OAuth 2.0 Desktop with a read-only scope; video-platform sessions are stored as browser cookies inside session_data/ and should be treated as credentials.

هیچ RBAC، JWT یا میان‌افزار نشست وجود ندارد — این یک اپلیکیشن دسکتاپ تک‌اپراتوره است. دسترسی فیزیکی به دستگاه معادل دسترسی کامل است. دسترسی Google Drive از OAuth 2.0 Desktop با اسکوپ فقط-خواندنی استفاده می‌کند؛ نشست‌های پلتفرم ویدیو به‌صورت کوکی مرورگر در session_data/ ذخیره می‌شوند و باید مانند اعتبارنامه با آن‌ها رفتار شود.
