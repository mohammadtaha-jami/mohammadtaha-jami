Y v1 OUTUBE CHANNEL MANAGER

Project: Video-Automation_Project — a Windows-first desktop automation system that scripts, voices, thumbnails, assembles, and publishes long-form and Shorts video for multiple isolated YouTube channel profiles.

پروژه: Video-Automation_Project — یک سیستم اتوماسیون دسکتاپ ویندوز‌محور که اسکریپت‌نویسی، صداگذاری، ساخت تامبنیل، مونتاژ و انتشار ویدیوهای بلند و Shorts را برای چندین پروفایل کانال یوتیوب به‌صورت مجزا انجام می‌دهد.

YouTube Channel Manager is a Windows-first desktop automation system that produces and publishes long-form videos and YouTube Shorts for multiple isolated channel profiles. Operators configure channels through a CustomTkinter GUI; each profile owns its own OAuth credentials, media assets, language/TTS settings, title queues, and a clock-based schedule. There is no application HTTP server and no relational database — persistence is a file-backed control plane (channels/channels.json plus per-channel JSON and directories). External systems are consumed as outbound APIs (Gemini, YouTube, TTS, Telegram).

YouTube Channel Manager یک سیستم اتوماسیون دسکتاپ ویندوز‌محور است که ویدیوهای بلند و YouTube Shorts را برای چندین پروفایل کانال مجزا تولید و منتشر می‌کند. اپراتورها از طریق رابط گرافیکی CustomTkinter تنظیمات را انجام می‌دهند؛ هر پروفایل اعتبارنامه OAuth، دارایی‌های رسانه‌ای، تنظیمات زبان/TTS، صف عناوین و برنامه زمانی خاص خود را دارد. هیچ سرور HTTP اپلیکیشنی و هیچ پایگاه‌داده رابطه‌ای وجود ندارد — ماندگاری داده از طریق فایل‌های کنترل (channels/channels.json به همراه JSON‌های هر کانال) مدیریت می‌شود.

Technical Objectives

اهداف فنی

  1. T1Isolate credentials per channel (and optionally per language) — distinct client_*.json and token*.pickle paths.جداسازی اعتبارنامه به ازای هر کانال (و اختیاری برای هر زبان) — مسیرهای مجزا برای client_*.json و token*.pickle.
  2. T2Deterministic title consumption — used_titles.json prevents duplicate long-form titles.مصرف قطعی عنوان — used_titles.json از تکرار عناوین بلند جلوگیری می‌کند.
  3. T3Language-aware media — pipeline cwd is channels/<name>/<language>/.رسانه زبان‌آگاه — دایرکتوری کاری پایپ‌لاین channels/<name>/<language>/ است.
  4. T4Survive TTS/API flakes — TTS exponential backoff; Gemini key rotation; YouTube backup OAuth.تحمل خطاهای TTS/API — عقب‌نشینی نمایی TTS؛ چرخش کلیدهای Gemini؛ OAuth پشتیبان YouTube.
  5. T5Operator visibility — status.json steps plus Telegram events.دیدپذیری اپراتور — مراحل status.json به همراه رویدادهای Telegram.
  6. T6Windows production workstation — Python 3.10+ (validated on 3.13), FFmpeg on PATH.ایستگاه کاری تولید ویندوز — Python 3.10+ (تأیید‌شده روی 3.13)، FFmpeg در PATH.

The system is a modular monolith on a single machine: one process for the GUI (operator control plane), one process per pipeline run (main.py --run-once or shortvideo.py), a synchronous subprocess chain for stages, and the file system as the integration bus. It is not microservices — modules communicate via CLI arguments, working-directory conventions, on-disk artifacts, and shared Python imports.

سیستم یک مونولیت ماژولار روی یک دستگاه است: یک فرآیند برای GUI، یک فرآیند به ازای هر اجرای پایپ‌لاین (main.py --run-once یا shortvideo.py)، زنجیره subprocess همزمان برای مراحل، و فایل‌سیستم به عنوان باس یکپارچه‌سازی. این میکروسرویس نیست — ماژول‌ها از طریق آرگومان‌های CLI، قراردادهای دایرکتوری کاری، فایل‌های روی دیسک و importهای مشترک پایتون ارتباط برقرار می‌کنند.

There is no SQL engine. The system of record is JSON documents plus blob-store folders: the registry channels/channels.json, per-language documents (schedule.json, used_titles.json, status.json, script.txt), and binary/secret files (OAuth JSON, token.pickle, media copies). Concurrency is best-effort — no transactions or foreign-key enforcement.

هیچ موتور SQL وجود ندارد. سیستم رکورد، مجموعه‌ای از اسناد JSON و پوشه‌های بلاب است: رجیستری channels/channels.json، اسناد هر زبان (schedule.json، used_titles.json، status.json، script.txt)، و فایل‌های باینری/محرمانه (OAuth JSON، token.pickle، کپی‌های رسانه). همزمانی best-effort است — هیچ تراکنش یا محدودیت foreign-key وجود ندارد.

Fieldفیلد Typeنوع Constraintsمحدودیت‌ها Descriptionتوضیح

The product does not expose an HTTP application API. Interfaces are CLI contracts, Python callables, and outbound HTTP to vendors. Status handling lives inside adapters, not a public REST layer.

محصول هیچ HTTP API اپلیکیشنی ارائه نمی‌دهد. رابط‌ها شامل قراردادهای CLI، callable‌های پایتون و HTTP خروجی به vendor‌ها هستند. مدیریت وضعیت داخل آداپتورها است، نه در یک لایه REST عمومی.

  2. ۲.ایجاد OAuth client نوع Desktop؛ دانلود JSON و مرور در GUI (تبدیل به client_1.json).
  3. ۳.اولین آپلود مرورگر را باز می‌کند؛ pickle در دایرکتوری زبان ذخیره می‌شود.
  4. ۴.آماده‌سازی کلاینت دوم برای failover کوتا (client_secrets_2.json).
  5. ۵.نصب FFmpeg و اضافه‌کردن به PATH سیستم.
  6. ۶.پشتیبان‌گیری از: channels.json، OAuth JSON، token.pickle، script.txt، used_titles.json.
