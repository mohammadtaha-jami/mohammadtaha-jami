T v1 EAM MANAGEMENT SYSTEM

Project: Team Management System (Baltazar Plus) — a full-stack, self-hosted platform centralizing attendance tracking, task assignment, daily reporting, and performance warnings for remote and hybrid teams.

پروژه: سامانه مدیریت تیم (Baltazar Plus) — یک پلتفرم کامل و خوداستقرار که ردیابی حضور و غیاب، تخصیص وظایف، گزارش‌دهی روزانه و اخطارهای عملکردی را برای تیم‌های ریموت و هیبریدی در یک سیستم واحد متمرکز می‌کند.

VERSION v1.0.0 STATUS Production-Ready OWNER Baltazar Team DEV MohammadTaha HosseinZadeh & Javid Zia Choose a chapter from the tabs → یک فصل از تب‌ها انتخاب کنید

The Team Management System is a full-stack, self-hosted platform designed to solve the problem of managing remote and hybrid teams by centralizing attendance tracking, task assignment, daily reporting, and performance warnings into a single unified system. It replaces scattered spreadsheets, manual check-ins, and ad-hoc Telegram messages with role-based dashboards (Admin, Supervisor, Employee), automated daily/weekly reports, a configurable warning & penalty engine, and seamless Telegram bot notifications.

سامانه مدیریت تیم یک پلتفرم کامل و خوداستقرار است که برای حل مشکل مدیریت تیم‌های ریموت و هیبریدی طراحی شده و ردیابی حضور و غیاب، تخصیص وظایف، گزارش‌دهی روزانه و اخطارهای عملکردی را در یک سیستم یکپارچه متمرکز می‌کند. این سامانه جایگزین اکسل‌های پراکنده، چک‌این‌های دستی و پیام‌های موردی تلگرام می‌شود؛ با داشبوردهای مبتنی بر نقش (مدیر، سرپرست، کارمند)، گزارش‌های خودکار روزانه/هفتگی، موتور اخطار و جریمه قابل‌پیکربندی و اعلان‌های یکپارچه از طریق ربات تلگرام.

The system follows a Monolithic Backend + SPA Frontend architecture with a modular Django app structure: Accounts, Tasks, Reports, Warnings, Calendar Events, and a Bot Scheduler, all behind a Django REST Framework API gateway with JWT authentication.

این سیستم از معماری بک‌اند مونولیتیک + فرانت‌اند SPA با ساختار ماژولار Django پیروی می‌کند: اپ‌های Accounts، Tasks، Reports، Warnings، Calendar Events و Bot Scheduler، همگی پشت یک API gateway مبتنی بر Django REST Framework با احراز هویت JWT.

The system of record is a relational database (SQLite for development, PostgreSQL for production) accessed exclusively through the Django ORM. Unique constraints enforce one report per user/task/day, one check-in per user/day, and one weekly report per user/week.

سیستم رکورد، یک پایگاه‌داده رابطه‌ای است (SQLite برای توسعه، PostgreSQL برای تولید) که فقط از طریق Django ORM در دسترس است. محدودیت‌های یکتایی، یک گزارش به ازای هر کاربر/وظیفه/روز، یک چک‌این به ازای هر کاربر/روز و یک گزارش هفتگی به ازای هر کاربر/هفته را تضمین می‌کند.

Data Flow

جریان داده

  1. 01Daily report — employee submits (12:00–22:00), manager verifies (until 23:00); non-complete status auto-creates a pending warning.گزارش روزانه — کارمند ثبت می‌کند (۱۲:۰۰–۲۲:۰۰)، مدیر تایید می‌کند (تا ۲۳:۰۰)؛ وضعیت غیر کامل به‌صورت خودکار اخطار در انتظار ایجاد می‌کند.
  2. 02Attendance — check-in/out creates and updates records; weekly report auto-generated every Saturday 08:00.حضور و غیاب — چک‌این/چک‌اوت رکورد ایجاد و به‌روزرسانی می‌کند؛ گزارش هفتگی هر شنبه ساعت ۰۸:۰۰ خودکار تولید می‌شود.
  3. 03Warning — created pending for 24 hours, then becomes active; 10 consecutive warning-free days remove one warning, all deletions logged.اخطار — ابتدا به مدت ۲۴ ساعت در انتظار، سپس فعال می‌شود؛ ۱۰ روز متوالی بدون اخطار، یک اخطار حذف می‌کند و همه حذف‌ها ثبت می‌شود.
  4. 04Telegram — daily 23:00 task reports, Saturday 08:00 weekly generation, Saturday 23:00 approval check.تلگرام — گزارش روزانه وظایف ساعت ۲۳:۰۰، تولید هفتگی شنبه ۰۸:۰۰، بررسی تایید شنبه ۲۳:۰۰.

A Django REST Framework API secured by JWT (SimpleJWT). Managers see all records; employees see only their own. Reports are time-window restricted (12:00–22:00) unless the task is an attendance task.

یک API مبتنی بر Django REST Framework که با JWT (SimpleJWT) امن شده است. مدیران همه رکوردها را می‌بینند؛ کارمندان فقط رکوردهای خود را. گزارش‌ها در بازه زمانی محدود هستند (۱۲:۰۰–۲۲:۰۰) مگر اینکه وظیفه از نوع حضور باشد.

Authentication Strategy

استراتژی احراز هویت

JWT via djangorestframework-simplejwt: short-lived access tokens (60 min) for API calls, long-lived refresh tokens (7 days) to renew access, and session authentication as a fallback for the Django admin.

JWT از طریق djangorestframework-simplejwt: توکن‌های access کوتاه‌مدت (۶۰ دقیقه) برای فراخوانی API، توکن‌های refresh بلندمدت (۷ روز) برای تمدید access، و احراز هویت session به‌عنوان پشتیبان برای پنل ادمین Django.

    C->>S: GET /api/tasks/ (Bearer access)

    Note over C: Access token expires (60 min)
    C->>S: POST /api/auth/refresh/
    S-->>C: 200 new access
    Note over C: Refresh token expires (7 days)
    C->>S: POST /api/auth/login/ (re-authenticate)
