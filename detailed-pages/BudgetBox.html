B v0 UDGETBOX

Product: BudgetBox — a team treasury and envelope-budgeting platform. A workspace holds a central operating balance and a set of boxes (liquidity envelopes); money is deposited, allocated into boxes, and spent as project or miscellaneous expenses and member payouts.

BudgetBox is a team treasury and envelope-budgeting platform. A single workspace owns a central operating balance and a set of boxes (liquidity envelopes). Money enters the workspace as deposits, is allocated into boxes, and is spent as project expenses, miscellaneous expenses, or member payouts. A project is a P&L reporting axis, not a second wallet — cash still lives in the treasury and in boxes; projects attach history and analytics. The product is a modular monolith: one FastAPI process, one PostgreSQL database, one React SPA, with a claymorphic bilingual (FA/EN, RTL/LTR) interface.

BudgetBox یک پلتفرم خزانه‌داری تیمی و بودجه‌بندی پاکتی است. یک workspace دارای یک بودجه جاری مرکزی (خزانه) و مجموعه‌ای از باکس‌ها (پاکت‌های نقدینگی) است. پول به‌صورت واریزی وارد workspace می‌شود، به باکس‌ها تخصیص می‌یابد و به‌عنوان هزینه پروژه، هزینه متفرقه یا پرداخت به اعضا خرج می‌شود. یک پروژه یک محور گزارش‌گیری سود و زیان است، نه یک کیف پول دوم — نقدینگی همچنان در خزانه و باکس‌ها باقی می‌ماند؛ پروژه‌ها فقط تاریخچه و تحلیل را به خود متصل می‌کنند. محصول یک مونولیت ماژولار است: یک فرآیند FastAPI، یک پایگاه‌داده PostgreSQL و یک SPA ری‌اکت با رابط کلی‌مورفیک دوزبانه (فارسی/انگلیسی، RTL/LTR).

Money Model

مدل مالی

Total workspace budget  =  current operating balance  +  Σ active box balances

Current operating       =  Σ treasury INCOME where source = central_wallet
                           − Σ treasury EXPENSE where source = central_wallet

Box balance              =  Σ box-ledger INCOME  −  Σ box-ledger EXPENSE

Allocate to box          =  treasury EXPENSE (kind=box_allocation) from central
                            + box INCOME (allocation_in)
                            (not new money)

Project expense          =  treasury EXPENSE (kind=project_expense) from central
                            (box optional)

budget_limit ≤ 0         =  unlimited box ceiling (no over-limit warning gate)

Technical Objectives

اهداف فنی

  1. T1Double-entry-like derived balances — never a mutable balance column on the wallet.موجودی‌های مشتق‌شده شبیه دوطرفه — هرگز ستون موجودی قابل‌تغییر روی کیف پول نیست.
  2. T2Row-level locks (SELECT … FOR UPDATE) on box and workspace wallet rows before mutating money.قفل سطح ردیف (SELECT … FOR UPDATE) روی ردیف باکس و کیف‌پول workspace پیش از تغییر پول.
  3. T3Alembic-only schema change in shared environments.تغییر schema فقط از طریق Alembic در محیط‌های مشترک.
  4. T4Bilingual UI (FA/EN) with Shamsi/Gregorian date formatting and Toman-style currency display.رابط دوزبانه (فارسی/انگلیسی) با قالب‌بندی تاریخ شمسی/میلادی و نمایش ارز به سبک تومان.
  5. T5Role-based access at workspace level (admin/editor/viewer) plus per-box membership for roster and split payouts.دسترسی مبتنی بر نقش در سطح workspace (admin/editor/viewer) به‌همراه عضویت هر باکس برای roster و پرداخت‌های تقسیم‌شده.

BudgetBox is not microservices. One ASGI app (app.main:app) owns auth, boxes, treasury, projects, and team. Isolation is layered, not networked: transport → API → schema → service → model → core. Hard rule: if a financial change is possible by editing only an endpoint file, layering is broken. The frontend mirrors the same idea — pages → hooks → services/api.ts → FastAPI, with components never calling fetch directly.

BudgetBox میکروسرویس نیست. یک اپلیکیشن ASGI (app.main:app) مسئول auth، باکس‌ها، خزانه، پروژه‌ها و تیم است. جداسازی لایه‌ای است نه شبکه‌ای: transport ← API ← schema ← service ← model ← core. قانون سخت: اگر یک تغییر مالی فقط با ویرایش فایل endpoint ممکن باشد، لایه‌بندی نقض شده است. فرانت‌اند همان الگو را دارد — pages ← hooks ← services/api.ts ← FastAPI، بدون فراخوانی مستقیم fetch در کامپوننت‌ها.

PostgreSQL 15. All money amounts are NUMERIC(12,2); primary keys are UUID v4. workspace_wallets holds no balance column — it exists solely as a lock row for SELECT … FOR UPDATE serialization. Central and box balances are always derived from the ledgers, never stored as a mutable column.

PostgreSQL 15. تمام مقادیر پولی NUMERIC(12,2) هستند؛ کلید اصلی UUID v4 است. workspace_wallets هیچ ستون موجودی ندارد — تنها به‌عنوان یک ردیف قفل برای سریال‌سازی SELECT … FOR UPDATE وجود دارد. موجودی مرکزی و باکس همیشه از دفترها مشتق می‌شود، هرگز به‌صورت ستون قابل‌تغییر ذخیره نمی‌شود.

Data-Flow Explanation

توضیح جریان داده

  1. 01Identity — users + hashed password; session = refresh_tokens (SHA-256 of refresh JWT).هویت — users + رمز هش‌شده؛ نشست = refresh_tokens (SHA-256 توکن رفرش).
  2. 02Tenancy — workspaces + workspace_members.role; all boxes/projects inherit workspace_id.Tenancy — workspaces + workspace_members.role؛ همه باکس‌ها/پروژه‌ها از workspace_id ارث می‌برند.
  3. 03Envelopes — boxes.budget_limit = 0 means unlimited; box_members is the assigned roster, not the whole workspace.پاکت‌ها — boxes.budget_limit = 0 یعنی نامحدود؛ box_members فقط roster تخصیص‌یافته است.
  4. 04Central cash — workspace_wallets is a lock row only; balance is computed from treasury_transactions.نقد مرکزی — workspace_wallets فقط ردیف قفل است؛ موجودی از treasury_transactions محاسبه می‌شود.
  5. 05Box cash — computed from transactions where box_id is set.نقد باکس — از transactions که box_id دارند محاسبه می‌شود.
  6. 06Projects — project_boxes optional; treasury project expenses do not require a linked box.پروژه‌ها — project_boxes اختیاری است؛ هزینه پروژه در خزانه نیازی به باکس متصل ندارد.
  7. 07Payouts — split box withdrawal creates one payouts row per recipient; dashboard "your share" sums these.پرداخت‌ها — برداشت تقسیم‌شده یک ردیف payouts به ازای هر گیرنده می‌سازد؛ «سهم شما» جمع این‌هاست.

Error Handling Model

مدل مدیریت خطا

Backend — Pydantic → FastAPI 422 with { "detail": [ { "loc", "msg", "type" } ] }. Business HTTPException(detail=str) → { "detail": "…" }. get_db rolls back on exception and always closes the session; services call UnitOfWork.commit() on success (explicit, not implicit).

بک‌اند — Pydantic ← FastAPI 422 با { "detail": [ { "loc", "msg", "type" } ] }. خطای کسب‌وکار HTTPException(detail=str) ← { "detail": "…" }. get_db در خطا rollback می‌کند و همیشه session را می‌بندد؛ سرویس‌ها در موفقیت UnitOfWork.commit() را صریحاً فراخوانی می‌کنند.

Frontend — apiFetch throws ApiError. 401 → refresh → retry; failure clears tokens (back to login). Modals show inline rose banners; destructive deletes also toast.
