Project: RagBot — a session-based Retrieval-Augmented Generation chatbot with an LLM-powered intent router, running entirely locally via Ollama with a per-session FAISS vector store and no external cloud dependencies.

RagBot is a session-based RAG chatbot with an LLM-powered intent router. The system ingests PDF documents or raw text into a per-session FAISS vector store and answers questions grounded in that knowledge — entirely locally via Ollama, with no external cloud dependencies. The core idea is conditional RAG: an intent router classifies each message as GREETING, KNOWLEDGE, or CHITCHAT, and only KNOWLEDGE questions trigger a FAISS lookup.

RagBot یک چت‌بات RAG جلسه‌محور با مسیریاب intent مبتنی بر LLM است. سیستم فایل‌های PDF یا متن خام را در یک vector store مجزای FAISS برای هر session بارگذاری می‌کند و پاسخ‌ها را بر پایه همان دانش، به‌طور کامل و محلی از طریق Ollama و بدون وابستگی به سرویس‌های ابری تولید می‌کند. ایده اصلی RAG شرطی است: مسیریاب intent هر پیام را به یکی از سه دسته GREETING، KNOWLEDGE یا CHITCHAT تقسیم می‌کند و فقط سوالات KNOWLEDGE جستجوی FAISS را فعال می‌کنند.

In Scope

در محدوده

Session-based chat with isolated FAISS stores, PDF/raw-text ingestion with recursive chunking, intent classification, conditional RAG with source previews, bounded conversation memory, a REST API (FastAPI) with a bundled RTL chat UI, and optional FAISS disk persistence.

چت جلسه‌محور با vector store مجزا، بارگذاری PDF/متن خام با chunking بازگشتی، طبقه‌بندی intent، RAG شرطی همراه با پیش‌نمایش منابع، حافظه محدود مکالمه، یک REST API (FastAPI) به همراه رابط چت RTL و ماندگاری اختیاری FAISS روی دیسک.

Out of Scope (v2.0)

خارج از محدوده (نسخه ۲.۰)

Multi-user authentication / RBAC, horizontal scaling or distributed vector stores, streaming responses (SSE/WebSocket), and cloud LLM providers (OpenAI, Anthropic, etc.).

احراز هویت چندکاربره / RBAC، مقیاس‌پذیری افقی یا vector store توزیع‌شده، پاسخ‌های استریم (SSE/WebSocket) و ارائه‌دهندگان LLM ابری (OpenAI، Anthropic و غیره).

Request Lifecycle

چرخه پردازش درخواست

sequenceDiagram
    participant U as User
    participant API as FastAPI
    participant P as RAGProcessor
    participant R as Router LLM
    participant F as FAISS
    participant C as Chat LLM
    U->>API: POST /api/chat
    API->>P: ask(session_id, question)
    P->>R: classify intent
    R-->>P: GREETING or KNOWLEDGE or CHITCHAT
    alt KNOWLEDGE
        P->>F: retrieve top-4 chunks
        F-->>P: relevant documents
        P->>C: RAG prompt with context
        C-->>P: grounded answer
    else GREETING/CHITCHAT
        P->>C: general chat prompt
        C-->>P: general answer
    end
    P-->>API: answer, sources, intent
    API-->>U: 200 JSON response

RagBot has no traditional SQL/NoSQL database. It relies on an in-memory session registry (dict[str, SessionState]), a per-session FAISS vector store, and optional disk persistence under data/faiss_sessions/{session_id}/.

RagBot هیچ پایگاه‌داده SQL/NoSQL سنتی ندارد. سیستم بر یک ثبت‌کننده session در حافظه (dict[str, SessionState])، یک vector store مجزای FAISS برای هر session و ماندگاری اختیاری روی دیسک در data/faiss_sessions/{session_id}/ تکیه می‌کند.

Scaling Considerations

ملاحظات مقیاس‌پذیری

  • Multiple users — session isolation already handles this; add rate limiting.
  • High concurrency — run multiple uvicorn workers.
  • Large knowledge base — increase CHUNK_SIZE; tune HNSW params.
  • Multi-node — replace in-memory sessions with Redis; FAISS → Qdrant/Weaviate.
  • چند کاربر — جداسازی session این را پوشش می‌دهد؛ افزودن rate limiting.
  • همزمانی بالا — اجرای چند worker uvicorn.
  • پایگاه دانش بزرگ — افزایش CHUNK_SIZE؛ تنظیم پارامترهای HNSW.
  • چند‌نودی — جایگزینی session‌های حافظه‌ای با Redis؛ FAISS → Qdrant/Weaviate.
