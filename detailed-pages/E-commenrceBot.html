T v1 ELEGRAM E-COMMERCE BOT

Project: Telegram WooCommerce Sync Bot — a production-grade storefront system that bridges a WooCommerce store with a Telegram bot interface via real-time, two-stage catalog synchronization.

پروژه: ربات تلگرامی همگام با ووکامرس — یک سیستم فروشگاهی سطح تولید که فروشگاه ووکامرس را از طریق همگام‌سازی دو مرحله‌ای و بلادرنگ کاتالوگ، به رابط ربات تلگرام متصل می‌کند.

The Telegram E-Commerce Bot is a production-grade storefront system that bridges a WooCommerce online store with a Telegram bot interface. It eliminates the dual-maintenance problem of keeping product data synchronized between a web store and a chat-based storefront by establishing WooCommerce as the single source of truth. The system pulls categories and products from the WooCommerce REST API, persists them into a local SQLite database, and serves them to end-users through a fully asynchronous Telegram bot with paginated inline keyboards. A Flask admin panel provides operational control — starting/stopping the bot, toggling a Telegram proxy, triggering on-demand catalog syncs, and inspecting the synced catalog via a JSON API and browser UI.

ربات فروشگاهی تلگرام (Telegram E-Commerce Bot) یک سیستم فروشگاهی سطح تولید است که فروشگاه آنلاین ووکامرس را به رابط ربات تلگرام متصل می‌کند. این سیستم با تعیین ووکامرس به عنوان منبع واحد حقیقت، مشکل نگهداری دوگانه داده محصولات میان فروشگاه وب و فروشگاه چت‌محور را از بین می‌برد. سیستم دسته‌بندی‌ها و محصولات را از REST API ووکامرس دریافت کرده، در یک پایگاه‌داده محلی SQLite ذخیره می‌کند و از طریق یک ربات تلگرام کاملاً ناهمزمان با کیبوردهای صفحه‌بندی‌شده به کاربران نمایش می‌دهد. یک پنل مدیریت Flask کنترل عملیاتی کامل فراهم می‌کند — روشن/خاموش کردن ربات، فعال/غیرفعال‌سازی پروکسی تلگرام، اجرای همگام‌سازی دستی کاتالوگ و بازبینی کاتالوگ همگام‌شده از طریق API و رابط مرورگر.

The system follows a modular monolith architecture with three primary runtime components: the Flask Admin Panel (main process, HTTP server, REST API, and bot lifecycle manager), the Telegram Bot (runs in a dedicated daemon thread with its own asyncio event loop), and the WooCommerce Sync Engine (an async HTTP client that pulls catalog data).

سیستم از معماری مونولیت ماژولار با سه مؤلفه اصلی زمان اجرا پیروی می‌کند: پنل مدیریت Flask (فرآیند اصلی، سرور HTTP، REST API و مدیریت چرخه حیات ربات)، ربات تلگرام (در یک نخ daemon اختصاصی با event loop مجزای asyncio اجرا می‌شود) و موتور همگام‌سازی ووکامرس (کلاینت HTTP ناهمزمانی که داده کاتالوگ را دریافت می‌کند).

The system persists two tables in a local SQLite database (products.db, accessed via aiosqlite): categories and products, connected by a one-to-many relationship. Both tables use upsert semantics so repeated syncs never create duplicates.

سیستم دو جدول را در یک پایگاه‌داده محلی SQLite (products.db، از طریق aiosqlite) ذخیره می‌کند: categories و products که با رابطه یک‌به‌چند به هم متصل‌اند. هر دو جدول از معنای upsert استفاده می‌کنند تا سینک‌های تکراری هرگز داده تکراری ایجاد نکنند.

Upsert Strategy

استراتژی Upsert

-- Categories
INSERT INTO categories (id, name, slug)
VALUES (?, ?, ?)
ON CONFLICT(id) DO UPDATE SET
    name = excluded.name,
    slug = excluded.slug;

-- Products
INSERT INTO products (id, category_id, name, description, price, permalink, image_url)
VALUES (?, ?, ?, ?, ?, ?, ?)
ON CONFLICT(id) DO UPDATE SET
    category_id = excluded.category_id,
    name        = excluded.name,
    description = excluded.description,
    price       = excluded.price,
    permalink   = excluded.permalink,
    image_url   = excluded.image_url;

Sync Pipeline

پایپ‌لاین سینک

  1. S1Categories — paginate GET /wp-json/wc/v3/products/categories?per_page=100&page=N until an empty page. Upsert each category.دسته‌بندی‌ها — صفحه‌بندی GET /wp-json/wc/v3/products/categories تا رسیدن به صفحه خالی. سپس upsert هر دسته.
  2. S2Products — read all category IDs from the local table; for each, paginate GET /wp-json/wc/v3/products?category={id}. Upsert each product.محصولات — خواندن شناسه همه دسته‌ها از جدول محلی؛ برای هرکدام صفحه‌بندی GET /wp-json/wc/v3/products?category={id}. سپس upsert هر محصول.

Pagination Query (bot browsing)

کوئری صفحه‌بندی (مرور در ربات)

SELECT id, category_id, name, description, price, permalink, image_url
FROM products
WHERE category_id = ?
ORDER BY id ASC
LIMIT ? OFFSET ?;
-- offset = (page - 1) * per_page

Orphan Handling

مدیریت محصولات یتیم

Products whose category_id no longer exists in categories are surfaced in the admin API under a synthetic "deleted category" group.

محصولاتی که category_id آن‌ها دیگر در categories وجود ندارد، در API ادمین تحت یک گروه مصنوعی «دسته حذف‌شده» نمایش داده می‌شوند.

The Flask admin panel exposes a small REST API with no authentication (single-operator deployment). The Telegram bot exposes commands and callback-data patterns for catalog browsing.

پنل مدیریت Flask یک REST API کوچک بدون احراز هویت (استقرار تک‌اپراتوره) ارائه می‌دهد. ربات تلگرام نیز دستورات و الگوهای callback-data برای مرور کاتالوگ را نمایش می‌دهد.

Security Best Practices Applied

اصول امنیتی رعایت‌شده

  • All credentials via .env; git-ignored, with a committed .env.example.تمام اعتبارنامه‌ها از طریق .env؛ در git-ignore با یک .env.example کامیت‌شده.
  • trust_env=False, proxy=None — prevents accidental proxy leakage of credentials.trust_env=False، proxy=None — از نشت تصادفی اعتبارنامه از طریق پروکسی جلوگیری می‌کند.
  • All user-facing product data escaped with html.escape() before rendering.تمام داده محصول رو به کاربر با html.escape() escape می‌شود.
  • callback_data strictly parsed with format validation; invalid data rejected.اعتبارسنجی سخت‌گیرانه فرمت callback_data؛ داده نامعتبر رد می‌شود.
  • Global error handler in PTB; try/except with logging throughout.error handler سراسری در PTB؛ try/except همراه با لاگ در سراسر کد.
  • Non-root container user (Dockerfile creates appuser, UID 1000).کاربر غیر-root در کانتینر (appuser، UID 1000).
  • All DB queries use parameterized statements (? placeholders) — no SQL injection surface.تمام کوئری‌های پایگاه‌داده پارامتریک هستند (?) — بدون سطح حمله SQL injection.
