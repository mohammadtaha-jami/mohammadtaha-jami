B v1 ALTAZAR CRM

Project: CRM-Baltazar — a self-hosted, sequential sales-pipeline CRM enforcing a five-stage funnel (Lead Hunter → SDR → Setter → PM → Closer) with a Persian RTL interface and Jalali calendar for teams operating in Iran.

پروژه: CRM-Baltazar — یک CRM خوداستقرار و پایپ‌لاین فروش ترتیبی که یک قیف پنج‌مرحله‌ای (شکارچی سرنخ → SDR → Setter → PM → Closer) را اجرا می‌کند، با رابط کاربری فارسی راست‌به‌چپ و تقویم جلالی برای تیم‌های فعال در ایران.

Baltazar CRM is a self-hosted, sequential sales-pipeline CRM that enforces a five-stage funnel: Lead Hunter (LH) → SDR → Setter → PM → Closer, with a sixth Admin persona for operations, analytics, user management, Excel import/export, and equal lead distribution. It replaces spreadsheets with role-specific dashboards, enforced stage transitions, duplicate-phone detection, a Jalali (Persian) calendar for Asia/Tehran operations, soft-delete with audit trail, and gamified scoring on approved meetings.

Baltazar CRM یک CRM خوداستقرار برای پایپ‌لاین فروش ترتیبی است که یک قیف پنج‌مرحله‌ای را اجرا می‌کند: شکارچی سرنخ (LH) → SDR → Setter → PM → Closer، به همراه نقش ششم Admin برای عملیات، تحلیل، مدیریت کاربران، ورود/خروج اکسل و توزیع عادلانه سرنخ‌ها. این سیستم صفحات‌گسترده را با داشبوردهای نقش‌محور، انتقال اجباری مراحل، تشخیص شماره تکراری، تقویم جلالی برای منطقه زمانی Asia/Tehran، حذف نرم با ردیابی و امتیازدهی بازی‌گونه هنگام تأیید جلسات جایگزین می‌کند.

High-Level Constraints

محدودیت‌های سطح بالا

  • Monolith, not microservices — domain modules are Flask blueprints + service functions, not independently deployable services.
  • Server-side rendering first — most "APIs" are HTML form POST endpoints; one JSON endpoint exists (admin user analytics).
  • SQLite-friendly migrations — no Alembic; column additions are listed in SCHEMA_PATCHES. Destructive resets use python seed.py --reset.
  • Demo credentials (admin / admin123, etc.) are for local seed only and must never ship to production unchanged.
  • مونولیت، نه میکروسرویس — ماژول‌های دامنه، blueprint و سرویس‌های Flask هستند، نه سرویس‌های مستقل قابل استقرار.
  • اولویت رندر سمت سرور — بیشتر «API»‌ها در واقع endpointهای فرم HTML هستند؛ فقط یک endpoint JSON (تحلیل کاربر Admin) وجود دارد.
  • مهاجرت سازگار با SQLite — بدون Alembic؛ افزودن ستون در SCHEMA_PATCHES فهرست شده. ریست مخرب با python seed.py --reset.
  • اعتبارنامه‌های دمو (admin / admin123 و غیره) فقط برای seed محلی هستند و نباید بدون تغییر به production بروند.

The system is a modular Flask monolith: server-rendered Jinja2 templates (Tailwind via CDN), WTForms + CSRF, Flask-Login sessions, and SQLAlchemy 2.x against SQLite by default (any SQLAlchemy URI, including PostgreSQL, via DATABASE_URL). Domain modules are Flask blueprints + service functions — small team, shared Lead aggregate, transactional stage updates.

سیستم یک مونولیت ماژولار Flask است: قالب‌های Jinja2 با رندر سمت سرور (Tailwind از CDN)، WTForms + CSRF، نشست‌های Flask-Login، و SQLAlchemy 2.x روی SQLite به‌صورت پیش‌فرض (هر URI سازگار با SQLAlchemy، از جمله PostgreSQL، از طریق DATABASE_URL). ماژول‌های دامنه blueprint و توابع سرویس Flask هستند — تیم کوچک، aggregate مشترک Lead، به‌روزرسانی تراکنشی مراحل.

Frontend Architecture Notes

نکات معماری فرانت‌اند

No SPA router — each role dashboard is a full page load. Styling via Tailwind Play CDN and the Dana font (production hardening should pin a built CSS bundle). CSRF hidden field via partials/csrf_input.html on every POST. The leaderboard modal loads from /rating-board/modal; admin lead detail uses HTML partials.

بدون SPA router — هر داشبورد نقش یک بارگذاری کامل صفحه است. استایل‌دهی از طریق Tailwind Play CDN و فونت دانا (سخت‌شدن تولید باید یک باندل CSS ساخته‌شده را ثابت کند). فیلد مخفی CSRF از طریق partials/csrf_input.html در هر POST. مودال جدول امتیازات از /rating-board/modal بارگذاری می‌شود.

There are two physical tables. The Lead row is a wide aggregate: LH identity, SDR assignment and call sheet, Setter meeting, PM proposal, Closer outcome, and admin archive metadata all live on one record. Relationships to users are multiple optional FKs (created_by, assigned SDR, processing agents, admin deleter).

دو جدول فیزیکی وجود دارد. ردیف Lead یک aggregate عریض است: هویت LH، تخصیص و برگه تماس SDR، جلسه Setter، پروپوزال PM، نتیجه Closer و متادیتای بایگانی admin همگی روی یک رکورد قرار دارند. ارتباط با users از طریق چندین FK اختیاری (created_by، SDR تخصیص‌یافته، عوامل پردازش، حذف‌کننده admin) است.

Soft delete: admin_deleted_at set; operational queries use Lead.active_only(). A second admin delete hard-deletes the row. Duplicate phones are currently an application-level scan of active leads, not a unique DB constraint.

حذف نرم: admin_deleted_at ست می‌شود؛ کوئری‌های عملیاتی از Lead.active_only() استفاده می‌کنند. حذف دوم توسط admin ردیف را به‌طور کامل حذف می‌کند. شماره‌های تکراری در حال حاضر یک اسکن سطح اپلیکیشن روی سرنخ‌های فعال است، نه یک محدودیت یکتای پایگاه‌داده.

Fieldفیلد Typeنوع Constraintsمحدودیت‌ها Descriptionتوضیح

This system is not a public JSON API. The interface is HTTP + HTML forms (and file downloads). Auth is a session cookie after POST /auth/login; RBAC failures return 403; CSRF failures return 400; success mutations redirect (302) with a flashed message (Post/Redirect/Get).

این سیستم یک API عمومی JSON نیست. رابط شامل HTTP + فرم‌های HTML (و دانلود فایل) است. احراز هویت یک کوکی نشست پس از POST /auth/login است؛ خطاهای RBAC کد 403 و خطاهای CSRF کد 400 برمی‌گردانند؛ تغییرات موفق با ریدایرکت (302) و پیام flash انجام می‌شوند (الگوی Post/Redirect/Get).

Applied Controls

کنترل‌های اعمال‌شده

  • Bcrypt password hashing; CSRF on all state-changing forms
  • RBAC decorator (@role_required); inactive users cannot be loaded into session
  • Upload type (.xlsx/.xls) and 16 MB size limits
  • Soft-delete instead of casual hard-delete; parameterized ORM queries (no string-concat SQL)
  • Open-redirect guard on admin lead edit/delete — next must start with /admin/
  • هش رمز عبور با Bcrypt؛ CSRF روی همه فرم‌های تغییردهنده وضعیت
  • دکوراتور RBAC (@role_required)؛ کاربران غیرفعال در نشست بارگذاری نمی‌شوند
  • محدودیت نوع فایل (.xlsx/.xls) و حجم ۱۶ مگابایت
  • حذف نرم به‌جای حذف کامل بی‌احتیاط؛ کوئری‌های ORM پارامتری‌شده
  • محافظ open-redirect در ویرایش/حذف سرنخ admin — next باید با /admin/ شروع شود
